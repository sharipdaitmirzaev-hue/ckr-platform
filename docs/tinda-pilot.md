# Пилот ЦКР — ООО ТИНДА

Этап 30: первый пилотный проект на реальной организации.  
Этап 32: применена методология ЦКР (текущий этап, стратегические цели, roadmap).  
Этап 33: Project Execution — рабочая дорожная карта, задачи, KPI.

Версия: `0.33.0-beta` · Связано: [project-execution.md](./project-execution.md) · [ckr-methodology.md](./ckr-methodology.md) · [closed-pilot.md](./closed-pilot.md) · [crm.md](./crm.md)

Новые бизнес-модули **не добавлялись**. Использованы существующие контуры ЦКР.

## 1. Цель пилота

Провести end-to-end сопровождение организации **ООО ТИНДА** на платформе ЦКР:

1. Зафиксировать организацию и проект оптовой платформы.  
2. Получить анализ и рекомендации Лии.  
3. Выстроить workspace с этапами реализации.  
4. Подготовить CRM-структуру (клиенты / поставщики / партнёры).  
5. Запустить пилотную сделку и репутационный профиль организации.  
6. Собрать проблемы и предложения по улучшению ЦКР.

## 3. Проект

**Название:** Развитие оптовой платформы ТИНДА  

| Блок | Содержание |
|---|---|
| Описание | Масштабирование оптовой B2B-платформы: ассортимент, продажи, партнёры, регионы |
| Текущие ресурсы | Клиентская база, команда, склад/логистика, кабинет в ЦКР |

- Подготовить оборотный капитал и экспертизу для масштабирования  
- Стандартизировать сопровождение сделок через ЦКР

## 4. Анализ Лии

Seed создаёт запись в `lia_analyses` (режим анализа + рекомендации по ресурсам).

### Результаты анализа (пилотная фиксация)

**Доступно**

- Действующая оптовая модель и клиентская база  
- Команда закупок и продаж  
- Складская / логистическая схема по ключевым SKU  
- Профиль организации и проект в ЦКР  

**Не хватает**

- Партнёры дистрибуции вне текущего региона  
- Оборотный капитал на расширение ассортимента  
- Экспертиза digital B2B-продаж и CRM-процесса  
- Инвестиционное / партнёрское финансирование  

**Рекомендации**

- Закрепить воронку «клиент → заявка → сделка»  
- Выделить 2–3 приоритетные категории ассортимента  
- Подключить поставщиков и партнёров через CRM + partnerships  
- Использовать Лию `find_solutions` для инвестиций и экспертов  
- Вести этапы workspace по плану ниже  

**Риски:** концентрация в одном регионе; узкий круг поставщиков; кассовый разрыв при росте; размытие фокуса.

Повторный живой прогон: кнопка анализа на карточке/редактировании проекта или `/api/lia/analyze`.

## 8. Как применить seed

Требуется: миграции до этапа 29, `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, секрет.

```bash
# терминал 1
npm run dev

# терминал 2
PILOT_SEED_SECRET=your-secret npm run seed:tinda
# или DEMO_SEED_SECRET=... npm run seed:tinda
```

API: `POST /api/pilot/tinda-seed` с заголовком `x-pilot-seed-secret`.  
В production по умолчанию отключён; для стенда пилота: `ALLOW_PILOT_SEED_IN_PRODUCTION=true`.

Учётная запись владельца после seed:

- email: `pilot.tinda@ckr.local`  
- пароль: `PilotTinda-ChangeMe!` (**сменить сразу**)

Данные: `src/lib/pilot/tinda-seed-data.ts` · apply: `src/lib/pilot/apply-tinda-seed.ts`.

## 9. Проблемы (обнаруженные / ожидаемые)

1. CRM RLS только для admin — оператор видит CRM через staff-доступ этапа 28, но seed `created_by` указывает на владельца ТИНДА (не admin); чтение через service/admin.  
2. Нет отдельных типов CRM «клиент / поставщик» — сегменты кодируются через `notes` + `company_name`.  
3. Живой `find_solutions` зависит от наполнения каталога и внешнего поиска; seed фиксирует анализ-fixture.  
4. Регион/город пилота заданы как Амурская область / Тында — при необходимости уточнить у организации.  
5. Повторный seed идемпотентен по UUID, но `analytics_events` / activity защищены проверками count.

Это первый реальный организационный контур closed pilot ЦКР.

## 11. Предложения по улучшению ЦКР

1. **CRM-сегменты** — явные tags/segments (`client` / `supplier` / `partner`) вместо текстовых notes.  
2. **Связь CRM ↔ organization** — `organization_id` на контактах и лидах.  
3. **Lia → workspace** — одной кнопкой создавать milestones из `next_steps` анализа.  
4. **Org dashboard** — сводка проекта + CRM + сделки в `/partner` без перехода в admin.  
5. **Pilot checklist UI** — чеклист сценария ТИНДА внутри `/admin/pilot`.  
6. **Безопасность seed** — отдельные роли `pilot_owner` и ротация пароля при первом входе.  
7. **Каталог решений** — больше trade-объектов для осмысленного `find_solutions` на Дальнем Востоке.
