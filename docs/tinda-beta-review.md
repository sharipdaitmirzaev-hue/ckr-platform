## Что использовалось

| Контур | Использование |
|---|---|
| Организация /partner | профиль, members, кабинет |
| Проект | оптовая платформа, стадии, публикация |
| Лия | аудит, стратегия, анализ, прогресс, outcome, pilot/beta insights |
| Workspace | roadmap, задачи, KPI, activity |
| CRM | клиенты / поставщики / партнёры, лиды |
| Сделки и репутация | пилотная сделка, trust-профиль |
| Outcomes | результаты и финансы |
| Pilot / beta ops | participants, checklist, beta-report |

---

## Какие функции дали пользу

1. **Единый контур проекта** — от профиля организации до workspace без отдельных систем.  
2. **Лия как навигатор** — структурирует следующий шаг (не заменяет решения команды).  
3. **Roadmap + KPI** — делают прогресс наблюдаемым для оператора ЦКР.  
4. **CRM-заготовка** — помогает держать сегменты B2B в одном месте с проектом.  
5. **Beta/pilot dashboard** — даёт управленческую видимость без новых модулей.

---

## Какие процессы были сложными

1. Дисциплина обновления KPI и статусов этапов.  
2. Переход от анализа Лии к заявкам/сделкам (разрыв «знание → действие»).  
3. CRM без явных сегментов — оператору приходится читать notes.  
4. Роли staff/admin при операциях CRM и модерации.  
5. Feedback не всегда превращался в `product_improvements` без ритуала.

---

## Какие улучшения нужны

Приоритет для Conditional Go (через `/admin/improvements`, не новые домены):

| Приоритет | Улучшение |
|---|---|
| high | Упростить путь «инсайт Лии → заявка/сделка» |
| high | Напоминания/UX обновления KPI в workspace |
| medium | Явные CRM-сегменты / фильтры |
| medium | Чеклист организации в beta-сценарии до `completed` |
| low | Больше trade-объектов каталога для find_solutions |

## Вывод для Public Launch

ТИНДА подтверждает: **платформа достаточна для сопровождения организации**.  
Ограничение — операционная дисциплина и UX текущих потоков, не отсутствие крупных модулей.

Рекомендация: оставить ТИНДА эталонным case волны 1 и закрыть high-улучшения до расширения доступа.
