# Case study: пилот ООО ТИНДА

Этап 31 · Версия `0.31.0-beta`  
Связано: [tinda-pilot.md](./tinda-pilot.md) · [tinda-improvements.md](./tinda-improvements.md) · [closed-pilot.md](./closed-pilot.md)

---

## 1. Исходная ситуация

**ООО ТИНДА** — оптовая торговая компания (регион: Амурская область / Тында), развивающая цифровую B2B-платформу закупок и поставок.

На старте пилота:

- бизнес уже работал (стадия `operating`), но не был упакован как проект ЦКР;
- не было единого контура «организация → проект → анализ → этапы → CRM → сделка»;
- потребность: структурировать развитие платформы и проверить готовность ЦКР к реальному кейсу.

---

## 2. Цель проекта

**Название:** Развитие оптовой платформы ТИНДА  

Цели пилота на ЦКР:

1. Зафиксировать организацию и проект развития.  
2. Получить анализ ресурсов и рекомендаций Лии.  
3. Выстроить workspace с этапами реализации.  
4. Подготовить CRM-сегменты: клиенты / поставщики / партнёры.  
5. Открыть пилотную сделку и репутационный профиль.  
6. Собрать проблемы продукта для улучшений.

Ориентир инвестиций в карточке проекта: 25 млн ₽ (на масштабирование ассортимента и партнёрской сети).

---

## 3. Использованные модули ЦКР

| Модуль | Применение в кейсе |
|---|---|
| `organizations` / `/partner` | Профиль ООО ТИНДА, owner membership |
| `projects` | Карточка проекта, статус `active` |
| `lia` | Анализ (`lia_analyses`): ресурсы, gaps, рекомендации |
| workspace | Milestones: подготовка → продажи → партнёры → масштабирование |
| `deals` | Пилотная сделка `negotiation` |
| `crm` | Сегменты контактов + лиды |
| `partnerships` | supplier / strategic |
| `analytics` | Pilot-метрики воронки |
| `reputation` | Профиль организации `verified` + history |
| Pilot Dashboard | Наблюдение `/admin/pilot` |

Seed: `npm run seed:tinda` · детали в [tinda-pilot.md](./tinda-pilot.md).

---

## 4. Результаты

После прохождения пилотного контура:

- организация и проект существуют в единой модели данных ЦКР;  
- Лия выдала структурированный анализ (доступно / не хватает / риски / next steps);  
- workspace содержит рабочие этапы развития;  
- CRM отражает три сегмента без реальных ПДн сотрудников;  
- сделка и репутация дают точку входа в сопровождение;  
- команда ЦКР получила список продуктовых пробелов (см. ниже).

Это первый **реальный организационный кейс** closed pilot, а не демо-каталог.

---

## 5. Проблемы

1. **CRM без сегментов** — «клиент / поставщик / партнёр» кодировались notes; нет first-class tags.  
2. **Нет связи CRM ↔ organization** — контакты не привязаны к `organization_id`.  
3. **Шаблон развития бизнеса отсутствовал** — описание проекта собиралось вручную.  
4. **Лия не имела сценария аудита действующего бизнеса** — только idea → project и analyze карточки.  
5. **Lia → workspace** — next_steps анализа не превращаются в milestones одной кнопкой.  
6. **Каталог trade на Дальнем Востоке** — `find_solutions` слабо наполнен под регион.  
7. **Операторский UX** — часть наблюдения в admin, часть в `/partner`, без единого org cockpit.
