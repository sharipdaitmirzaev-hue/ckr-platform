# Продуктовое тестирование ЦКР

Этап 19: проверка не только кода, а пользовательских сценариев перед реальным использованием.

Админ-контроль: `/admin/product-tests`  
Миграция: `supabase/migrations/20260325280000_product_tests.sql`

---

## Принцип

ЦКР — платформа комплексных решений. Тестируем путь участника:

```text
Идея → Анализ → Решения → Ресурсы → Реализация
```

Лия только рекомендует. Публичная карточка ≠ кабинет проекта.

---

## Сценарии

### 1. Предприниматель

```text
Регистрация → Выбор роли → Лия → Создание проекта → Публикация
```

| Проверка | Ожидание |
|---|---|
| UX | Понятный онбординг и первый шаг |
| Понятность | Лия объясняет следующий шаг |
| Ошибки | Нет тупиков при создании/публикации |

**Статус:** `pending` / `in_progress` / `passed` / `failed` / `blocked`

---

### 2. Инвестор

```text
Регистрация → Каталог проектов → Карточка → Заявка
```

| Проверка | Ожидание |
|---|---|
| Каталог | Проекты читаемы, карточка даёт контекст |
| Заявка | Отправляется, владелец получает сигнал |

---

### 3. Владелец возможности

```text
Создание возможности → Публикация → Получение заявки
```

| Проверка | Ожидание |
|---|---|
| Создание | Форма и типы возможностей понятны |
| Заявка | Входящая видна в кабинете |

---

### 4. Эксперт

```text
Создание профиля → Публикация → Получение запроса
```

| Проверка | Ожидание |
|---|---|
| Профиль | Специализация и услуги видны в каталоге |
| Запрос | Заявка на экспертизу доходит |

---

### 5. Полный цикл ЦКР

```text
Идея → Проект → Анализ Лией → Поиск решений →
Инвестор → Заявка → Сделка → Workspace
```

| Проверка | Ожидание |
|---|---|
| Анализ | Отчёт Лии понятен, без автодействий |
| Сделка | Создаётся в кабинете проекта |
| Workspace | Участники, этапы, история доступны |

## Рекомендации

| Тема | Рекомендация |
|---|---|
| Онбординг | Держать персональный путь по роли на первом экране |
| Demo | Перед показом включать `NEXT_PUBLIC_DEMO_MODE` |
| Лия | Не обещать автосоздание сущностей без подтверждения |
| Сделки | Подчёркивать разницу публичной карточки и workspace |
| Seed | Перед демо прогонять `npm run seed:demo` или fallback |

## Админ: `/admin/product-tests`

Возможности:

1. **Начать прогон** сценария — создаёт запись с чеклистом  
2. **Отметить проверки**, статус, результат  
3. **Зафиксировать проблемы и рекомендации**  
4. **Создать тестовую задачу** вне сценария  
5. **Сохранить результат** задачи

Доступ: только `admin` (RLS + `requireAdmin`).

---

## Как проводить прогон

1. Открыть `/admin/product-tests`  
2. Нажать «Начать прогон» у сценария  
3. Пройти шаги в UI от лица роли  
4. Отметить чеклист и статус  
5. Записать проблемы и рекомендации  
6. При необходимости создать точечные задачи
