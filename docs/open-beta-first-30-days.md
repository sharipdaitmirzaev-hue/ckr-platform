# Open Beta — первые 30 дней

Операционный план после активации **Open Beta Wave 1**.

Связано: [open-beta-launch-control.md](./open-beta-launch-control.md) · [open-beta-launch-plan.md](./open-beta-launch-plan.md)

---

## Неделя 1 — первые пользователи

- Применить миграцию волны и проверить `/admin/open-beta`.
- Создать invites (`source=open_beta_wave`, канал email/partner/referral).
- Провести предпринимателей по пути: регистрация → роль → профиль → Лия → проект.
- Ежедневно: Critical queue · активация · health check.

---

## Неделя 2 — анализ поведения

- Смотреть воронку и потери на `/admin/open-beta`.
- Сравнить роли: проекты, интересы, запросы, партнёрства.
- Собрать feedback по категориям UX / Lia / Project / Expert / Investment / Other.
- Продвинуть блокеры: feedback → pilot_issues → product_improvements.

---

## Неделя 3 — улучшения

- Закрыть High/Critical из очереди improvements (без новых модулей).
- Усилить empty states / CTA / сценарии Лии по найденным потерям.
- Донабрать экспертов и инвесторов, если связи слабые.
- Повторить OpenBetaHealthCheck.

---

## Неделя 4 — решение по расширению

- Срез метрик vs критерии успеха.
- Лия: «Как проходит открытый запуск ЦКР?» → `OpenBetaReport`.
- Решение: продолжить Wave 1 / расширить когорту / пауза.
- Зафиксировать выводы в changelog и ops-notes.

---

1. Critical = 0  
2. Активность когорты  
3. Новые feedback / issues  

## Еженедельный минимум

1. Воронка и drop-off
