# Open Beta Launch Plan

План контролируемого открытия доступа ЦКР после положительного Open Beta Readiness.

Связано: [open-beta-readiness.md](./open-beta-readiness.md) · [beta-expansion.md](./beta-expansion.md)

---

## Кого приглашаем

| Волна | Аудитория | Объём (ориентир) |
|---|---|---|
| Wave A | Предприниматели с идеей / действующим бизнесом | 40–60 |
| Wave B | Эксперты + инвесторы | 15–25 |
| Wave C | Организации / партнёры | 10–15 |

Источник приглашений: `beta_invites` (ручной / партнёр / реферал).  
Не открывать анонимный массовый signup без мониторинга Critical.

---

## Порядок волн

1. **Закрыть readiness** — `/admin/open-beta-review` → решение `open_beta`.
2. **Wave A** — предприниматели: регистрация → роль → профиль → Лия → проект.
3. **Wave B** — эксперты и инвесторы: профиль / интерес / запросы.
4. **Wave C** — организации: профиль → возможности → партнёры.
5. **Ревью 14 / 30 дней** — активация, связи, issues → continue / expand / pause.

---

## Метрики

### Активация

- ≥70% приглашённых завершили регистрацию  
- ≥60% заполнили профиль  
- ≥40% использовали Лию  
- ≥25% создали первый объект  

### Экосистема

- рост проектов и интересов;
- заявки между ролями;
- первые сделки / партнёрства;
- Critical issues = 0 в проде.

---

## Критерии успеха (30 дней)

- Решение Open Beta Review остаётся `open_beta` или улучшается.
- Нет открытых Critical; High ≤ 3 и в работе.
- Есть повторяемые успешные пути по каждой роли.
- Feedback loop работает: feedback → pilot_issues → product_improvements.
- Кейсы/демо (ТИНДА + новые) достаточны для онбординга.

---

## План первых 30 дней

| Дни | Фокус |
|---|---|
| 1–3 | Миграции, lint/build, env/security checklist, стартовые invites Wave A |
| 4–10 | Онбординг предпринимателей, сценарии Лии, проекты |
| 11–17 | Wave B: эксперты и инвесторы, интересы и запросы |
| 18–24 | Wave C: организации, возможности, партнёрства |
| 25–30 | Review на `/admin/open-beta-review`, решение continue / expand / pause |

Ежедневно: Critical queue · активация · связи.  
Еженедельно: срез метрик и feedback loop.

---

## Что не делаем

- Не добавляем новые крупные бизнес-модули.
- Не открываем публичный signup без операционного контроля.
- Не меняем решение «вслепую» — только по данным readiness и когорты.
