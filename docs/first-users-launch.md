# Запуск первых реальных пользователей

Этап 49 · Версия `0.49.0-beta`  
Подготовка публичной платформы ЦКР к первым настоящим пользователям — без новых крупных бизнес-модулей.

Связано: [public-marketplace.md](./public-marketplace.md) · [analytics.md](./analytics.md) · [verification.md](./verification.md) · [projects.md](./projects.md)

---

## Цель

Сделать понятный, доверительный и измеримый первый опыт:

- доверие к платформе;
- ясный путь после регистрации;
- демо-контент без персональных данных;
- модерация перед публикацией;
- аналитика воронки первого запуска.

---

## Кого приглашаем

Небольшая первая волна (ручной отбор):

| Роль | Зачем |
|---|---|
| Предприниматель | Создать проект / пройти Лию |
| Инвестор | Найти проект, оставить интерес |
| Эксперт | Создать профиль и пройти verification |
| Организация | Создать профиль `/partner` |

Предпочтение: участники, уже знакомые с кейсом ТИНДА или с понятной задачей (идея, ресурс, экспертиза).

---

## Сценарии, которые проверяем

Общий путь:

```text
Главная → Регистрация → Выбор роли → Онбординг → Первое действие
```

По ролям:

| Роль | Первое действие |
|---|---|
| Предприниматель | Создать проект (форма или Лия) |
| Инвестор | Найти проект в `/projects` |
| Эксперт | Создать профиль `/dashboard/expert` |
| Организация | Создать профиль `/partner` |

После регистрации в кабинете показывается блок **«Что хотите сделать?»** с вариантами, связанными с Лией и каталогами.

Публичные страницы доверия и контента:

- `/trust` — что такое ЦКР, как работает, принципы;
- `/cases` — кейс ТИНДА (задача / что было / что сделал ЦКР / результат);
- каталоги с пометкой **Демонстрационный** на seed-объектах.

---

## Модерация перед публикацией

Существующие жизненные циклы (не расширяем):

| Сущность | Путь публикации |
|---|---|
| Проекты | `draft` → `moderation` → `published` |
| Эксперты | статус профиля + `verification` |
| Инвестиции | статус с этапом `moderation` |
| Возможности | статус с этапом `moderation` |

Оператор проверяет через admin-модерацию / verification. Демо-seed не подменяет реальную модерацию пользовательского контента.

## Метрики первого запуска

События `analytics_events` (через существующий `trackAnalyticsEvent` / `trackBetaMilestone`):

| Событие | Когда |
|---|---|
| `public_page_view` | Просмотр публичной страницы |
| `registration_started` | Открытие `/register` |
| `registration_completed` | Успешный `signUp` |
| `role_selected` | Онбординг / выбор роли |
| `lia_started` | Первое использование Лии (milestone) |
| `first_object_created` | Первый проект / возможность / инвестиция / эксперт / организация |

Смотрим воронку:

```text
public_page_view
  → registration_started
  → registration_completed
  → role_selected
  → lia_started / first_object_created
```

Админ-аналитика: `/admin/analytics` и launch/beta-отчёты.

---

## Критерии успеха

Минимальный успех первой волны:

1. Пользователь регистрируется и выбирает роль без тупика.
2. Не менее одного осмысленного первого действия на роль (см. таблицу выше).
3. Публичный контент понятен: `/trust`, `/cases`, демо-каталог с метками.
4. Новый пользовательский объект не попадает в каталог минуя модерацию/verification.
5. События воронки пишутся в analytics и позволяют увидеть отвал.

Неуспех / стоп-сигналы:

- массовые ошибки регистрации или онбординга;
- публикация без модерации;
- путаница демо и реальных объектов;
- отсутствие первого действия у большинства приглашённых.

---

## Что не делаем на этом этапе

- Новые крупные бизнес-модули;
- отдельный продукт «маркетплейс 2.0»;
- расширение CRM / billing / API для мобильных клиентов.

Фокус — готовность к первым настоящим пользователям на уже созданной платформе.
