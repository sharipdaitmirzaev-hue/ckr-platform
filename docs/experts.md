# Модуль «Эксперты и расширенные профили» — ЦКР

## Роль экспертов

Эксперт — участник системы доверия ЦКР.

Он показывает:

- специализацию и компетенции;
- опыт и услуги;
- регион работы;
- статус публикации и проверки.

Эксперт не «продаёт услугу на витрине», а входит в экосистему проекта: идея → анализ → ресурсы → партнёры → реализация.

---

| Код | Смысл |
|---|---|

| `engineer` | Инженер |
| `builder` | Строитель |
| `consultant` | Консультант |
| `other` | Другое |

---

## Статусы профиля эксперта

| Статус | Смысл |
|---|---|
| `draft` | Черновик, виден только владельцу |
| `moderation` | На проверке перед каталогом |
| `published` | В публичном каталоге `/experts` |
| `archived` | Скрыт из каталога |

---

## Структура `expert_profiles`

| Поле | Описание |
|---|---|
| `id` | uuid |
| `user_id` | Владелец (1 профиль на пользователя) |
| `specialization` | Специализация |
| `headline` | Короткий заголовок |
| `description` | Опыт и компетенции |
| `experience_years` | Опыт в годах |
| `services` | Услуги |
| `region` | Регион |
| `status` | Статус публикации |
| `created_at` / `updated_at` | Служебные |

---

## Расширение `profiles` (доверие)

| Поле | Описание |
|---|---|
| `company_name` | Компания |
| `website` | Сайт |
| `social_links` | JSON: telegram / linkedin / vk / … |
| `verification_status` | Статус проверки участника |

Статусы проверки:

| Статус | Смысл |
|---|---|
| `unverified` | Не проверен |
| `pending` | Запрошена проверка |
| `verified` | Проверен ЦКР |

Публикация экспертного профиля и запрос проверки поднимают доверие к участнику. Финальный `verified` выставляет администратор (внешний процесс / admin-модуль).

## Страницы

| Маршрут | Назначение |
|---|---|
| `/experts` | Каталог опубликованных экспертов |
| `/expert/[id]` | Карточка эксперта |
| `/dashboard/expert` | Управление своим профилем |
| `/dashboard/expert/create` | Создание |
| `/dashboard/expert/edit` | Редактирование |

Карточка показывает: имя, специализацию, опыт, описание, регион, услуги, статус проверки.

---

## Связь с проектами

1. На странице проекта блок **«Нужен эксперт»** показывает релевантных `published` экспертов по региону.  
2. Кнопка **«Нужен эксперт»** создаёт заявку `applications` с `target_type = project`.  
3. На карточке эксперта кнопка **«Отправить заявку эксперту»** создаёт заявку с `target_type = expert`.  

Связка: `expert_profiles ↔ applications ↔ projects`.

---

## RLS

| Кто | Правило |
|---|---|
| Гости / anon | Видят только `published` |
| Эксперт | Создаёт и редактирует свой профиль (`user_id = auth.uid()`) |
| Admin | Полный доступ |

Хелперы заявок (`owns_application_target`, `get_application_target_owner`) учитывают `target_type = expert`.

---

## Поток публикации

1. Пользователь создаёт профиль в `/dashboard/expert/create`.  
2. Роль `expert` добавляется в `user_roles` (если ещё нет).  
3. Статус `draft` / `moderation` / `published` задаётся владельцем.  
4. В каталог попадают только `published`.  
5. При создании профиля `verification_status` участника переводится в `pending`, если был `unverified`.
