## Фактические данные

Что ЦКР реально сделал / мог зафиксировать по контуру ТИНДА (пилот):

| Область | Факт |
|---|---|
| Организация | Профиль ООО ТИНДА в `organizations` |
| Проект | Карточка развития оптовой платформы |
| Анализ | Сценарии Лии (аудит / стратегия / сопровождение) |
| Workspace | Этапы реализации, активность |
| CRM | Сегменты контактов / лиды |
| Партнёрства / сделки | Пилотные связи в экосистеме (без обязательной оплаты) |
| Оплаченная выручка ЦКР | **Не зафиксирована** как paid в платформе |

Итог факта: коммерческая ценность пилота — в упаковке бизнеса, процессе и доверии, а не в проведённом платеже.

---

## Какие услуги ЦКР релевантны кейсу

Стартовый набор (цена по запросу, пока админ не задаст):

1. **Аудит бизнеса** — диагностика operating-бизнеса.  
2. **Подготовка проекта** — карточка развития в ЦКР.  
3. **Поиск партнёров** — поставщики / стратегические партнёры.  
4. **Поиск инвестиций** — при масштабировании.  
5. **Проектное сопровождение** — workspace и сделки.  
6. **Юридическое / экспертное сопровождение** — договоры и экспертиза.

Фактически «оказанными» в пилоте ближе всего пункты 1–2 и элементы 5 (процесс), без выставленного счёта в системе.

## Результаты (нефинансовые)

- единый контур организация → проект → анализ → этапы;
- проверка готовности платформы к реальному кейсу;
- материал для product improvements;
- эталон пути Project Acquisition / Partnership.

## Потенциальная модель монетизации

*Не является фактом оплаты.*

| Модель | Как могла бы применяться |
|---|---|
| Услуга «Аудит бизнеса» | Разовый пакет после подтверждения объёма |
| «Подготовка проекта» + сопровождение | Фикс или этапный retainer |
| Комиссия со сделки | `%` или fixed от успешной сделки в ЦКР |
| Подписка company / enterprise | Доступ команды к кабинету и приоритету |
| Партнёрский канал | Attribution `source=partner` без автовыплат на этапе 63 |

Рекомендуемый порядок фиксации в платформе:

1. Создать/обновить услугу с ценой (admin).  
2. Связать работу с проектом ТИНДА.  
3. Открыть deal (`service` / `partnership`) с комиссией.  
4. Выставить `revenue_status`: potential → agreed → invoiced → paid.  
5. Оплату провести вне системы или через будущий PaymentProvider (сейчас mock).

## Ограничения

- не записывать paid без реального подтверждения;
- не смешивать сумму сделки сторон с выручкой ЦКР;
- PartnerRevenueMetrics — аналитика, не выплаты.
