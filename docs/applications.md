# Модуль «Заявки и взаимодействия» — ЦКР

## Назначение

Заявки — универсальный канал связи между участниками платформы.

Через заявку пользователь может откликнуться:

- на **проект**;
- на **возможность**;
- на **инвестиционное предложение** (модуль позже);
- на **экспертную услугу** (модуль позже).

Это не публичный комментарий и не чат сразу.  
Сначала заявка → решение владельца → затем (в будущем) диалог.

---

## Типы взаимодействий (`target_type`)

| Тип | Объект |
|---|---|
| `project` | Проект |
| `opportunity` | Возможность |
| `investment` | Инвестиционное предложение |
| `expert` | Экспертная услуга |

На Этапе 4 полностью работают `project` и `opportunity`.  
`investment` и `expert` заложены в схему.

---

## Статусы

| Статус | Смысл |
|---|---|
| `new` | Новая заявка |
| `reviewing` | На рассмотрении у владельца |
| `accepted` | Принята (создаётся заготовка conversation) |
| `rejected` | Отклонена |
| `closed` | Закрыта |

Владелец объекта может перевести заявку в `reviewing` / `accepted` / `rejected` / `closed`.

---

## Структура `applications`

| Поле | Описание |
|---|---|
| `id` | uuid |
| `from_user_id` | Отправитель |
| `target_type` | Тип объекта |
| `target_id` | id объекта |
| `message` | Текст заявки |
| `status` | Статус |
| `created_at` / `updated_at` | Служебные |

---

## Уведомления

Таблица `notifications`:

- при создании заявки trigger уведомляет владельца объекта;
- при смене статуса владелец может инициировать уведомление отправителю (RPC `create_notification`).

---

## Основа для messages

После `accepted` создаются:

- `conversations` (1:1 с заявкой);
- `conversation_members` (отправитель + владелец);
- `messages` (таблица готова, UI чата — следующий этап).

---

## RLS

Пользователь видит:

- свои **исходящие** заявки (`from_user_id = auth.uid()`);
- **входящие** по своим объектам (`owns_application_target`).

Другие пользователи заявки не видят.
