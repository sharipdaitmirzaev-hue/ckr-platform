## 2. Процесс приглашения

### Таблица `beta_invites`

| Поле | Описание |
|---|---|
| email | Кому выдано приглашение |
| code | Код вида `CKR-XXXXXXXX` |
| role | Роль при регистрации |
| status | `created` → `sent` → `used` / `expired` |
| created_at / used_at | Даты жизненного цикла |

### Админка `/admin/invites`

1. Создать приглашение (email + роль).
2. Передать код участнику (ссылка `/register?invite=CKR-...`).
3. Отметить «Отправлено» или сразу создать со статусом `sent`.
4. При необходимости **отключить** (`expired`).

### Регистрация

- Поле «Код приглашения» на `/register`.
- Если `NEXT_PUBLIC_BETA_REQUIRE_INVITE=true` — код обязателен.
- Email должен совпадать с приглашением.
- Роль берётся из приглашения; статус становится `used`.

Рекомендация для closed beta: отключить обязательное подтверждение email в Supabase Auth, чтобы сессия создавалась сразу и роль назначалась в том же шаге.

Опирайтесь на сценарии этапа 19 (`/admin/product-tests` и [product-testing.md](./product-testing.md)):

## 4. Сбор обратной связи

### Кнопка FeedbackButton

Глобальная кнопка «Обратная связь»:

- типы: `bug` · `idea` · `question` · `review`
- сообщение, оценка 1–5, текущая страница
- таблица `feedback`

### Оценка сценариев

После действий пишется `user_feedback_events` и показывается prompt:

| Событие | Когда |
|---|---|
| `project_created` | создание проекта (форма и Лия) |
| `application_sent` | отправка заявки |
| `opportunity_created` | создание возможности |
| `investment_created` | создание инвестиции |

Пользователь ставит оценку 1–5 или закрывает «Позже».

### Как работать с отзывами

1. Смотреть `feedback` и `user_feedback_events` в Supabase (admin RLS).
2. Критичные баги — в продуктовые тесты / задачи (`/admin/product-tests`).
3. Идеи — в backlog этапов roadmap.
4. Не публиковать персональные данные из обратной связи.
