# Pilot Operations ЦКР

Этап 36: подготовка закрытого пилота и сбор реальных данных использования.  
Версия: `0.36.0-beta` · Связано: [closed-pilot.md](./closed-pilot.md) · [tinda-pilot-progress.md](./tinda-pilot-progress.md) · [tinda-pilot.md](./tinda-pilot.md)

Новые крупные бизнес-модули **не добавлялись**. Цель — проверить уже созданную платформу.

---

## Правила пилота

1. Участие только по приглашению (`beta_invites`, `NEXT_PUBLIC_BETA_REQUIRE_INVITE=true`).
2. Каждый участник фиксируется в `pilot_participants` с ролью и статусом.
3. Прохождение сопровождается чеклистом `pilot_checklists`.
4. Обратная связь обязательна: категория + приоритет в `feedback`.
5. Лия в пилоте **только анализирует** (в т.ч. сценарий «Что мешает проекту двигаться?»).
6. Не расширять продукт новыми направлениями бизнеса во время пилота.

Кабинет оператора: `/admin/pilot` · отчёт: `/admin/pilot/report`.

---

## Роли

| Роль (`pilot_participants.role`) | Назначение |
|---|---|
| `entrepreneur` | Владелец / команда проекта |
| `investor` | Инвестор / капитал |
| `expert` | Эксперт ЦКР |
| `organization` | Организация-партнёр (напр. ТИНДА) |
| `operator` | Оператор ЦКР |

Статусы: `invited` → `active` → `inactive` / `completed`.

## Метрики

### Воронка (`/admin/pilot/report`)

```text
Регистрация → Профиль → Проект → Активность → Заявка → Сделка
```

### Использование

- Лия (сессии)
- Проекты
- CRM (заявки / сделки)
- Workspace (события `project_activity`)
- Сообщения

### Pilot Dashboard блоки

- **Участники** — приглашённые / зарегистрированные / профиль / активные  
- **Проекты** — созданные / активные / без активности / по стадиям  
- **Активность** — Лия, заявки, сделки, сообщения, workspace  

События воронки также пишутся в `analytics_events` (см. [closed-pilot.md](./closed-pilot.md)).

## Чеклист участника

Типовые пункты `pilot_checklists`:

1. Создал профиль  
2. Прошёл онбординг  
3. Создал проект  
4. Использовал Лию  
5. Отправил заявку  
6. Получил результат  

Статусы пункта: `pending` | `done` | `skipped`.

---

## Сбор обратной связи

Форма «Обратная связь» (глобальная кнопка) пишет в `feedback`.

### Категории

| Тип | Смысл |
|---|---|
| `bug` | Ошибка |
| `ux` | UX / удобство |
| `idea` | Идея улучшения |
| `business_value` | Бизнес-ценность |
| `lia_quality` | Качество ответов Лии |
| `question` / `review` | Совместимость с beta |

### Приоритет

`low` · `medium` · `high` · `critical`

Оператор просматривает ленту на `/admin/pilot`, критичные пункты заводит в `pilot_issues`.

## Лия для пилота

Сценарий: **«Что мешает проекту двигаться?»** (`pilot_insight`).

Анализирует: активность, roadmap, задачи, KPI, сделки.  
Результат: `PilotInsightReport` —

- `summary`
- `blocked_projects`
- `inactive_users`
- `recommendations`
- `next_actions`

Лия **не изменяет** данные проекта и участников.

---

## Критерии успешного запуска пилота

| Критерий | Ориентир |
|---|---|
| Участники в `pilot_participants` | ≥ целевой когорты (см. closed-pilot) |
| Профиль завершён | ≥ 70% зарегистрированных |
| Проект создан | ≥ 50% предпринимателей |
| Использование Лии | ≥ 1 сессия на активного участника |
| Feedback | ≥ 1 сообщение на участника, есть `business_value` / `lia_quality` |
| ТИНДА | roadmap / KPI / результаты обновляются, чеклист ведётся |
| Блокеры | нет unresolved `critical` issues > 7 дней |

При выполнении — готовность к расширению когорты (не к новым бизнес-модулям).
